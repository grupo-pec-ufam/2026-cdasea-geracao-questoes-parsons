# Quadro Kanban (GitHub Projects)

Um único quadro pode reunir as issues de vários repositórios, o que dá a você (orientador) uma visão de todos os projetos ao mesmo tempo, e a cada aluno a visão do seu.

## Como criar

1. Na página da sua **organização** (ou do seu perfil), abra a aba **Projects** e clique em **New project**.
2. Escolha o modelo **Board** (quadro).
3. Dê um nome (ex.: "Iniciação Científica - Grupo CER").

## Colunas (campo "Status")

Ajuste o campo **Status** para ter exatamente estas colunas, nesta ordem:

1. **Backlog** - ideias e tarefas futuras, ainda não priorizadas
2. **Esta semana** - o que foi combinado para a semana atual
3. **Em andamento** - o que está sendo feito agora
4. **Travado** - parado esperando algo (dado, resposta, decisão)
5. **Em revisão** - feito, aguardando o orientador
6. **Concluído** - encerrado

## Ligando as issues ao quadro

- Dentro do quadro, use **+ Add item** e depois **Add item from repository** para puxar issues existentes, ou digite `#` para buscar.
- Para automatizar: em **Workflows** (dentro do Projects), ative regras como "quando uma issue é fechada, mover para Concluído" e "quando uma issue é aberta, adicionar ao Backlog".

## Visões úteis (Views)

O Projects permite salvar mais de uma "visão" dos mesmos dados:

- **Por status** (o quadro Kanban em si), para o dia a dia.
- **Por responsável** (agrupando pelo campo Assignees), para você ver rapidamente a carga de cada aluno.
- **Tabela filtrada por projeto/label**, quando quiser olhar um único projeto de perto.

## Dica de adoção

Não configure tudo de uma vez. Comece com um projeto piloto: crie o quadro, cadastre as dez ou quinze primeiras tarefas como issues, e rode duas ou três semanas com a cadência semanal. Quando o fluxo estiver natural, replique para os demais projetos.
